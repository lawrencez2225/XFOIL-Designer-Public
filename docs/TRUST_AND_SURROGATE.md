# 数据可信度与代理模型

这份文档说明三件在原有工作流之外新增的事：**哪些求解结果可以相信**、
**如何把它们整理成一张表**、以及**如何在这张表上训练一个可用的近似模型**。

核心前提是一句警告，它贯穿全文：

> **收敛标记不能代表物理有效。**

## 1. 为什么需要判断可信度

XFOIL 对一条已经大面积分离的极曲线，仍然会报告：

```csv
status,convergence_rate,failed_alphas
ok,1.0,[]
```

同一批数据里的边界层显示：前缘分离泡与后缘分离**同时出现在同一表面上**，
峰值形状因子超过 9。而 XFOIL 官方手册（`XFOIL_6.996/doc/xfoil_doc.txt`）明确
声明它只支持：

- `limited trailing edge separation`（有限后缘分离）
- 不支持 `massive separation`（大分离）
- 不支持 `shocked flows`（激波流动）

**更麻烦的是**：边界层是逐点续算的，每一点用上一点的解做初值。所以即使物理
上早已失效，求解器仍能"收敛"出一个自我一致的解。实测四条校准曲线一路"收敛"
到 20°、零失败——**收敛失败标记不了有效域边界**。

只有物理量能定位边界。

2026-10-07 修正了工况导出、几何归一化和分离长度的计算。本文旧版实测误差与有效域边界不能作为修正后算法的验收结果；应从本地原始数据重新生成报告和训练模型。

## 2. 判定层：`xfoil_mac/analysis/trust.py`

判定基于**分离拓扑**，而不是单个阈值：

| 状态 | 含义 | 判定 |
|---|---|---|
| 全附着 | 无分离段 | `ok` |
| 单段后缘分离 | 一个分离段，位于弦长后部 | `ok` |
| 单段前缘泡 | 一个分离段，位于前缘附近 | `ok` |
| **两端同时存在** | 前缘泡与后缘分离同时在同一表面 | **`suspect`** |
| **单段覆盖大部分弦长** | 分离长度超过 25% | **`suspect`** |

外加两条：

- **`invalid`**：显式收敛失败，或边界层数据损坏、截断、与保存的几何不匹配
- **`unchecked`**：该运行没有保存边界层，**没有证据**——不是"通过"
- **`retry`**：孤立的数值失败（两侧相邻点都收敛）——**不是有效域边界**

分离长度按完整翼型的归一化弦向坐标 `x/c` 计算，相邻面板间假设 `Cf` 线性变化，用零点确定分离段端点。长度占比不再使用点数占比。25% 是暂定的筛查阈值；旧版按点数得到的校准不适用于此长度判据，也不能用它证明物理有效。

### 一个被移除的判据

早期版本用"峰值形状因子 > 8.0"作为判据。实测证明它**不可比跨几何**：

在 NACA 0012（Re=3.7e5）上，它在 α=4.5~5.0° 触发、却在 5.5~8.0° 不触发——
**真实的有效域边界不可能在角度上非单调**。触发点位于 x≈0.99 的后缘，描述的
是翼型厚度而非求解器失效。

已从判定中移除，仅作为证据保留。阈值常数 `EXTREME_SHAPE_FACTOR = 30` 的注释
里记录了这段经过。

### 旧版验收结果（修正后需重新校准）

在 16 个实测工况上（4 翼型 × 4 工况，NACA 0012/2412/4412/0021）：

- α ≥ 11° **全部被标出**
- 完全附着的 5.25°~7° 区间**零误标**
- 两个孤立失败点（α=−3.0、4.25）正确归类为 `retry`

## 3. 有效域表格：`xfoil_mac/analysis/domain.py`

把逐点判定汇总成**每个运行一行**的表格，输出
`xfoil_runs/datasets/domain_*.csv`：

| 列 | 内容 |
|---|---|
| `last_trusted_alpha` | 该配置下可信的 α 上界 |
| `first_suspect_alpha` | 首次被标记的角度 |
| `first_failed_alpha` | 首次求解失败的角度 |
| `cl_max` / `alpha_at_cl_max` | 极曲线峰值 |
| `verdicts` | 各判定计数 |

实测分布（16 个精确工况）：**最小 9.0°、中位 11.0°、最大 13.0°**。
边界随翼型与工况变化，**不是常数**。

## 4. 数据集：`xfoil_mac/storage/dataset.py`

把散落在各目录的结果整理成一张表，输出 `xfoil_runs/datasets/dataset_*.csv`
和一份 provenance（记录每个源文件的 SHA256）。

### 两条被强制执行而不是假设的规则

**1. 失败点保留行**
求解失败的 α **不会出现在 `polar.csv` 里**。如果按 polar 遍历，它会**静默消失**
——让一片区域看起来"从未采样"，而实际上是"采样了并被拒绝"。
代码把"请求的 α"与"失败的 α"取并集，失败点保留其位置、数值留空。

**2. 无边界层数据 = `unchecked`，不是通过**
148 行历史数据因为没有保存边界层而无法判定。它们被标为 `unchecked` 并记录
`has_boundary_layer=False`，**没有被当成合格数据**。

数据集中的 `re`、`mach` 是逐点实际工况，`re_reference`、`mach_reference` 是请求的参考工况。TYPE 2 按 `sqrt(CL_reference / CL)` 换算 Re 和 Mach，TYPE 3 按 `CL_reference / CL` 换算 Re，Mach 固定。Re、Mach、CL 均无量纲；失败或不可定义的工况留空并记录 `condition_status`。数据集格式版本为 2。

### 缩略语说明

判定用词刻意避免"失速"：

- 说 **"超出求解器有效域"** 或 **"分离占比过大"**
- **不说"失速"**

因为求解器失效不等于真实流动失速。这条纪律与
[adaptive.py](../xfoil_mac/adaptive.py)、
[diagnostics.py](../xfoil_mac/analysis/diagnostics.py) 保持一致。

## 5. 采样计划：`xfoil_mac/analysis/sampling.py`

按"求解次数是唯一贵资源"的原则，把请求范围变成两段式网格：

- **线性区**：粗步长
- **非线性区到有效域上界**：细步长

并用**实测迭代次数**给每个点定价（实测：大攻角处计算量是小攻角的 15 倍）。

### 域感知估计

为**尚未求解**的翼型做计划时，上界取**邻域已测工况的最小值**，而不是中位数——
同一工况下不同翼型的上界相差 3.5°，新翼型无法预判落在分布哪里。

**优先级**：具体扫描的实测证据 > 群体统计 > 默认值。

`DEFAULT_DOMAIN_LIMIT = 11.0` 只在**完全没有测量证据**时使用，且注释里写明它
是 16 个工况的中位数、范围 9~13°。

## 6. 形状描述符：`xfoil_mac/analysis/shape.py`

数据集的形状信息只有两个标量：峰值厚度、峰值弯度。

**这不够**：峰值厚度分不出"厚在前缘"和"厚在中段"，而**俯仰力矩取决于分布
而非峰值**。树模型只能按给定列切分，所以必须把分布本身喂给它。

描述符在固定弦向位置采样厚度分布与弯度分布，共 22 维：

```
0.02  0.06  0.14  0.25  0.36  0.47  0.58  0.69  0.80  0.85  0.90
```

铺满全弦而非集中在前缘——**后缘区域正是峰值标量无法描述、而俯仰力矩由它决定
的地方**。

几何先平移、旋转并将 x、y 同时按弦长归一化。训练优先读取该次计算的 `geometry.dat`，同名但不同形状的计算分别处理；有保存目录却缺少几何时不回退到翼型库。归一化版本为 2，旧模型加载时会明确要求重新训练。

### 读不到形状的行会被拒绝，而不是填零

过滤缺失形状后会重新检查实际训练行数、运行数与工况变化，留出划分也只包含形状可读的运行。

填零等于告诉模型"这是个平直翼型"，是**错误信息**而非缺失值。调用方可以从
`rows_without_shape` 知道丢了多少（当前约 0.9%）。

## 7. 代理模型：`xfoil_mac/analysis/surrogate.py`

### 31 个特征

| 类别 | 数量 | 内容 |
|---|---|---|
| 原始 | 6 | 厚度比、厚度位置、最大弯度、Re、Mach、α |
| 派生 | 3 | 弯度/厚度、厚度×α、弯度×厚度 |
| 形状 | 22 | 沿弦长的厚度与弯度分布 |

### 三条方法论纪律

**1. 测试集必须在拟合前预留**

模型选择和性能汇报**不能**用同一批数据。随机留出**数据点**是错的——同一运行的
相邻 α 高度相关，模型只是在"背答案"。所以按**整个运行**分组划分。

**2. 固定种子 + 审计日志**

```
SPLIT_SEED = 20260101
```

划分必须可复现，否则可以反复换划分直到得到好看的数字。每次在测试集上出报告
都**追加**一行到 `xfoil_runs/models/experiments.jsonl`——测试集被反复查看就
不再是测试集了，有了日志这件事变成可核查的。

**3. 误差按 trust 分层报告**

只报汇总 MAE 会被可信区的好成绩掩盖失效区的崩坏。实测 CD 在 trusted 区
0.00108、flagged 区 0.00330——**差 3 倍**。

### 旧版实测结果（20464 行 / 4865 运行，预留测试集 842 运行）

| 目标 | MAE | 95% 置信区间 | 占数据跨度 |
|---|---|---|---|
| CD | 0.00125 | [0.00115, 0.00135] | **0.53%** |
| CL | 0.02086 | [0.01983, 0.02199] | **0.65%** |
| CM | 0.00428 | [0.00406, 0.00452] | **0.81%** |

### 特征演进（实测）

| 阶段 | 特征数 | CL 占跨度 | CD | CM |
|---|---|---|---|---|
| 起点（29 运行、单一工况） | 6 | 0.81%* | 0.50%* | 1.18%* |
| 几何扩展到 1431 个翼型 | 6 | 2.59% | 0.94% | 3.79% |
| + 3 个派生特征 | 9 | 1.40% | 0.66% | 2.35% |
| **+ 22 个形状描述符** | **31** | **0.65%** | **0.53%** | **0.81%** |

\* 起点的数字是**窄域假象**（只覆盖 13 个几何）。现在的数字覆盖
**1431 个几何、7 个工况**。

**结论**：最大的杠杆是**特征表达**，不是数据量。补充第三个工况只改善
0.03 个百分点，而形状描述符改善了 0.75 个百分点。

## 8. 怎么实操

### 模型版本要求

`xfoil_runs/models/surrogate_latest.joblib` 指向最新训练的模型。只有元数据中的 `descriptor_version=2` 才能加载；旧模型必须重新生成数据集并训练。下面的预测输出保留为旧版格式示例，不是当前模型的验证结果。

### 查一个翼型在给定工况下的气动系数

```sh
conda activate xfoil-work
python surrogate_tool.py predict --airfoil=naca2412 --re=500000 --mach=0.10
```

输出：

```
模型     surrogate_latest.joblib
特征     31 个  (含形状 22 个, 16317 行训练)
对象     naca2412
工况     Re=500,000  Mach=0.10

  alpha        CL         CD         CM   备注
--------------------------------------------------------------
  -4.00   -0.1934    0.01035   -0.05551
  -2.00    0.0053    0.00780   -0.05399
   0.00    0.2609    0.00734   -0.05361
   2.00    0.4774    0.00770   -0.05570
   4.00    0.7226    0.00894   -0.05360
   6.00    0.8639    0.01069   -0.04864
   8.00    1.1141    0.01528   -0.03923

全部行的输入都在训练范围内（插值）。
```

### 用自己导入的翼型

```sh
python surrogate_tool.py predict --coordinates=/path/to/my_airfoil.dat \
    --re=800000 --mach=0.15 --alphas="-2 0 2 4 6"
```

### 看模型是在插值还是外推

`备注` 列是关键。树模型**在任何输入上都会给出数字**，它没有能力拒绝回答。
所以超出训练范围的行会被标为 `外推` 并列出具体哪个特征越界：

```
  14.00    1.42    0.0382   -0.0521   外推  alpha=14 outside [-4, 20] ...
```

**外推的行不应直接采信。**

### 重新训练（数据增加后）

```sh
python surrogate_tool.py train
```

数据不足时会**拒绝拟合并列出缺口**，例如：

```
拒绝拟合:
  A fit was not attempted. mach takes 1 distinct value(s); need 4 to
  learn it. Solve more configurations before expecting transferable
  predictions.
```

### 怎么判断它对你的场景好不好用

**最重要的一步：拿它和真实求解对照。** 流程是——

1. 用 `predict` 得到一组预测
2. 在工作台里对**同一个翼型、同一个工况**跑一次真实求解
3. 比较两者

对照时有两个坑，我都踩过：

- **必须排除空目标值的行**。求解失败的 α 在数据集里是空值，混进对照会得出虚高的误差
- **必须匹配 Re 和 Mach**。同一个翼型名在数据集里可能对应多个工况

参考量级（全部在预留测试集上实测）：CL 约 0.02、CD 约 0.001、CM 约 0.004。
如果你的对照结果远大于此，先检查上面两点，再怀疑模型。

### 一个已知的诚实结论

实测发现**训练集内误差与留出误差几乎相同**（CL 0.0189 vs 0.0162）——
说明当前模型**不是过拟合，而是欠拟合**。也就是说还有提升空间，方向是更丰富的
特征或更大的模型容量，不是更多数据。

## 9. 批次工具

### `watch_batch.py` —— 进度监测

```bash
python watch_batch.py --expected=1612
```

只读 `run.json`，**不碰求解器**，所以批次运行期间可以随时执行。输出进度、速率、
预计完成时间、状态分布、可用率，以及距最后一次落盘的秒数（超过 2 分钟会提示
批次可能已停止）。

### `analyse_batch.py` —— 一键分析

```bash
python analyse_batch.py --folds=4          # 单批次
python analyse_batch.py --all --folds=4    # 跨全部批次
```

依次运行：有效域表格 → 数据集 → 充分性 → 预留运行评分。

**单批次模式只读自己的目录**，不会静默混入其他工况；只有显式 `--all` 才跨批次。
数据少于 `MIN_ROWS` 或某个特征取值不足时，会**拒绝拟合并列出缺口**，而不是给出
一个好看的过拟合分数。

## 10. 边界与已知限制

- **有效域上界依赖测量**。默认值 11.0° 来自 16 个工况，不是通用常数。
- **UIUC 批次的 α 分辨率粗**（每翼型 4 个点，−4/0/4/8°），所以那批数据推出的
  有效域上界只能落在 8°。生产矩阵那 16 个工况用的是 0.5° 网格。
- **形状描述符使用无量纲坐标**，整体缩放、平移与旋转不改变厚度和弯度特征。
- **`parallel.py` 未接入任何现有路径**。实测 2 worker 加速 1.17x、4 worker
  1.68x、**8 worker 比串行更慢**，收益不足以承担改动已被测试覆盖的科学函数
  的风险。
- **"不收敛"不等于"失速"**。判定措辞与阈值注释都遵循这条。

## 12. 本地记录与公开分享

本地原始记录保留绝对路径与计算哈希，用于复现。工作台打包只选择已知的科学结果文件，生成脱敏副本；JSON、CSV、HTML 中的本地路径转为结果目录内的相对路径或脱敏标记。日志、预设、模型、隐藏文件与未知文件不打包，原记录不覆盖。`SHARING.txt` 说明包内哈希对应本地原件，分享包不能用作续算检查点。

本地运行目录和 AVL 安装目录不纳入 Git。含私人信息的自定义输入、日志和结果不能推送；需要分享时检查脱敏副本及图表中的自定义名称。
