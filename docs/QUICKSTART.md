# 日常速查

**一句话：日常什么都不用改，报告页会自动告诉你数据能不能信。**

---

## 日常使用

### 双击 `启动工作台.command`

和以前一样。唯一区别：**每次计算完的报告页顶部多一张可信度卡片，数据表末尾多一列「可信度」。**

```
数据可信度
可信角度上界约 10°。 首次标记出现在 12°。
[可信 8] [超出有效域 2]
▸ 判定依据
```

### 看到 `超出有效域` 时怎么办

它**不是错误**——数据仍然保留、仍然有效，只是不该依赖它。

| 你的目的 | 建议 |
|---|---|
| 看气动趋势 | 可用，但**别往更高 α 外推** |
| 拿去训练模型 | 会进入误差更大的 `flagged` 层（CD 差约 3 倍） |
| 判定 `cl_max` / 失速边界 | **不要用这些点** |
| 对照实验数据 | 可用，但要知道求解器在此处本身不可靠 |

判定的含义是"**求解器超出了它文档声明支持的范围**"，不是"真实流动失速"。

## 辅助工具

激活环境后使用：

```sh
cd XFOIL-Designer-Public          # 你的克隆目录
conda activate xfoil-work
```

### 预测一个翼型，并和真值对照

```sh
python check_airfoil.py naca2412 --re=500000 --mach=0.10
```

把预测和**已有真值并排列出**，直接说明模型在这个翼型上准不准。这是判断"能不能信模型"最快的方法。

用自己的坐标文件：

```sh
python check_airfoil.py /path/to/my_airfoil.dat --re=800000 --mach=0.15
```

### 从整个翼型库里找候选

```sh
python prescreen.py --re=500000 --mach=0.10 --target-cl=0.8 --keep=40
```

扫全部 1615 个翼型，输出 40 个候选按预测升阻比排序。

**实测排序质量**：Spearman 0.88（全库）到 1.00（设计搜索候选）。

**但短名单是筛子，不是答案**——实测代理选出的"最优"只达到真实最优的约 68%，入选的仍需真实求解。

### 在设计的多工况搜索里启用预筛

工作台的设计搜索默认**逐个真算**。想先排序，在配置里加：

```json
"prescreen": true
```

启用后候选先被排序，**被保留的仍然真算**——搜索会记录 `surrogate_vs_solved` 来验证模型。

## 定期维护

工作台每算一次，数据**自动进数据集**。但**模型不会自动更新**。

```sh
python surrogate_tool.py train
```

**什么时候该重训**：

| 信号 | 动作 |
|---|---|
| 攒了几百行新数据 | 重训一次 |
| `check_airfoil.py` 的对照误差明显大于参考量级 | 重训 |
| 数据集行数比模型训练行数多出很多 | 重训 |

**参考量级**（预留测试集实测）：**CL ≈ 0.02、CD ≈ 0.001、CM ≈ 0.004**

查看当前状态：

```sh
python surrogate_tool.py info
```

### 跑一批计算时看进度

```sh
python watch_batch.py --expected=1612
```

只读已写出的结果文件，**不碰求解器**，批次运行期间可以随时执行。

### 全库分析

```sh
python analyse_batch.py --all     # 跨全部批次，能拟合
python analyse_batch.py           # 单批次，只有一个工况时会拒绝拟合
```

输出：有效域表格 → 数据集 → 充分性 → 留出评估（含分层误差与置信区间）。

## Re 和 Mach 为什么要一起看

**Re 和 Mach 是两个独立的无量纲数，不是一一对应的。**

$$\mathrm{Re} = \frac{\rho V c}{\mu} \qquad M = \frac{V}{a}$$

| 量 | 依赖什么 | 回答什么问题 |
|---|---|---|
| **Mach** | 速度 V、声速 a | **可压缩性**有多重要 |
| **Re** | 速度 V、**弦长 c**、密度 ρ、黏度 μ | **黏性效应**相对惯性有多重要 |

固定弦长和流体时 `Re ∝ V`、`M ∝ V`，看起来像一一对应。**但弦长是设计选择**——机翼弦长 1~10 m、螺旋桨叶片可能 0.05 m——**弦长一变，这个比例就断了**。

本机数据里就同时存在 **Mach=0.1 对应三个不同 Re**（50 万 / 698,895 / 233 万），因为弦长取了 0.3 m 或 1.0 m，黏度取了 2e-05 或 1.7894e-05。

### 这为什么要小心

**XFOIL 会接受任意一对 (Re, Mach) 并求解**，即使这一对在物理上无法由同一组弦长和流体同时成立。求解结果内部是自洽的，所以这类问题**很难事后发现**。

所以每次计算都会记录 `flow_relation`，说明这一对是怎么来的：

| 值 | 含义 |
|---|---|
| `derived_re_from_mach` | 只给了 Mach，Re 由假设推出（推荐） |
| `derived_mach_from_re` | 只给了 Re，Mach 由假设推出 |
| `both_matched` | 两个都给了，且与所述假设一致 |
| **`independent`** | **两个都给了且不一致**——有意为之，用于非物理工况 |
| `unverified` | 旧记录，没有流体假设，无法核对 |

**推荐做法：只给 Re 或只给 Mach 之一**，让另一个由假设推出。

### 检查整个数据档案

```sh
python audit_data.py
```

它会用每个 run 自己的假设反推 Re，列出对不上的那些。

## 三条注意

**1. 别把某张卡上的角度当成常数**

实测跨 16 个工况的范围是 **9.0 ~ 13.0°，中位 11.0°**：

| 翼型 | 可信上界 |
|---|---|
| NACA0012 | 12.5 ~ 13.0° |
| NACA2412 | 10.5 ~ 11.5° |
| NACA4412 | 9.5° |
| NACA0021 | 9.0 ~ 11.5° |

每张卡的角度只对**那一次计算**负责。

**2. 长批次不要用 `nohup ... &`**

shell 的后台进程会随调用结束被终止。用受管后台任务，并用 `watch_batch.py` 看进度。

**3. 模型和数据都不进 Git**

`xfoil_runs/` 被 `.gitignore` 排除，所以**克隆仓库后没有数据和模型**。需要用 `surrogate_tool.py train` 重新训练（前提是本机已有求解数据）。

## 常见问题

**报告页没有可信度卡片？**

计算时没开 `boundary_layer`——判定需要边界层数据。

**全部显示「可信」？**

α 范围没跨过边界。边界通常在 9~13°，所以只扫到 8° 是不会触发的。

**全部显示「无证据」？**

边界层文件没找到。

**`prescreen.py` 说没有模型？**

先跑 `python surrogate_tool.py train`。

**预测被标为「外推」？**

输入超出了训练数据的取值范围。小幅越界（15% 以内）已容忍；超出会被标出并列出具体是哪个特征越界。外推的行不应直接采信。
